원본 `logs/`는 로컬에 남는다.

## 실행 규칙

- 중간 음성은 강조만 허용하고, 확정 발화마다 별도 실행 ID를 부여한다.
- 유효한 JSON 단계 전체를 받은 뒤 대상, 현재 배치, 도착지와 겹침을 검사한다.
  중단된 응답의 부분 JSON은 실행하지 않는다. 실패한 단계 뒤의 단계도 중단한다.
- 같은 발화의 동일 이동은 한 번만 반영한다. 새 발화의 의도적인 재교환은 허용한다.
- 숫자 이동은 현재 특정된 비교/이동 대상으로 제한한다. 불명확한 음성은 보류한다.
- 두 숫자의 명시적 교환과 버블 정렬의 인접 이동은 현재 자리로 로컬 계획을 만든다.
  이미 맞는 순서의 방향 설명은 강조만 하고, 명시적인 재교환은 별개로 허용한다.
- 명시적인 전체 정렬 요청이며 한 행의 숫자들이 판독돼 있으면 현재 자리의 순열을
  로컬에서 계산한다. 반복 요청은 이미 정렬된 순서를 뒤집지 않는다.
- 짧고 덧그어진 밑줄도 숫자 후보에서 제외한다. 글자에 획이 추가/삭제되면 재판독한다.
- 흐름은 화살표, 가리킨 궤적, 서로 다른 객체를 잇는 선에만 허용한다.
- 페이지 전환 시 발화, 비교 대상, 대기 요청과 이전 응답을 무효화한다.
- 마이크 종료/오류/재연결을 기록하고 일시적인 중단은 제한된 횟수로 재연결한다.

## 데이터와 평가의 의미

`inputs`는 원본 이벤트 번호와 상대 시간, 필기·interim·final을 보존한다.
과거 로그는 서버 도착 순서가 뒤집힌 경우가 있어 이벤트 번호로 정렬한다.
`observedRead`는 당시 AI 판독값이다. `read`는 이미지/사례를 검토해 붙인 정답 값이며
둘을 자동으로 같은 값으로 만들지 않는다. 모호한 발화의 의도는 정답으로 추측하지 않는다.

`checks`는 최종 순서 외에 `unchanged`와 `forbiddenMoved`를 지원한다.
한 번 움직였다가 돌아온 경우도 이동 금지 검사에서 실패한다.
흐름 검사는 기대 경로 외의 경로가 추가돼도 실패한다.

```sh
npm test
npm run build

# 실제 API 비용이 발생한다. 기본은 모든 라벨된 사례 × 3회, 통과 기준 90%.
npm run eval

# 한 사례를 먼저 측정
EVAL_RUNS=1 EVAL_CASE=real-sort-013822 npm run eval

# 원래 시간 간격으로 입력을 겹쳐 재생
EVAL_MODE=timed EVAL_RUNS=1 EVAL_CASE=real-sort-013822 npm run eval
```

순차 모드는 필기를 먼저 넣고 발화마다 처리가 끝날 때까지 기다린다.
시간 재현 모드는 원래 간격으로 입력을 넣고 다음 확정 발화 직전에 직전 결과를 검사한다.
두 모드 모두 검토된 손글씨 라벨을 공급하므로 **실제 OCR/마이크 정확도 평가는 아니다**.
`inputs` 없는 예전 사례는 시간 재현 모드에서도 순차로 실행된다.
TCP/혈액순환 원본에는 확정 음성이 없어 현재 API 순차 평가에서 제외되며,
실측 회귀 테스트와 다음 브라우저 실측의 경로 검증에 사용한다.

보고서는 `logs/eval-*.md`에 저장한다. 단계 정확도와 모든 검사항목을 통과한 사례 수를
함께 표시하며, 기준 미달이면 테스트가 실패한다. 단일 실행의 통과를 일반 정확도로
해석하지 않는다. 새 실측 세션을 보정에 사용하지 않은 검증용 데이터로 추가해야 한다.

임계값은 보정용만 보고 고르고, 검증용 점수는 결과 확인에만 쓴다.

### 획 라벨 (`strokeLabels`)

`node scripts/render-case.mjs <사례>`가 획 id와 현재 Board 묶음을 그린 PNG를 만든다. 그림을 보고
`[{ strokes, role, value? }]`를 붙인다.

- `digit`: 이 획들이 정확히 한 객체이고 값 후보(`board.values()`)여야 한다. 모르는 숫자는 `value`를 비운다.
- `frame`·`underline`·`arrow`·`circle`: 각 획이 값 후보에 들어가면 안 된다.
- `other`: 판단 보류(점, 위쪽 낙서 등). 채점하지 않는다.

`src/evals/strokes.test.ts`가 API 없이 채점하고 기준선 아래로 떨어지면 실패한다.
상세 표는 `STROKE_REPORT=1 npx vitest run src/evals/strokes.test.ts --silent=false`.

기준선(정렬 13개 사례):

| | 숫자 묶음 | 값 아님 획 | 행 전체 정답 |
| --- | --- | --- | --- |

검증용 실패는 모두 같은 원인이다. 작은 화면에서는 칸 구분선(높이 약 160px)이 `b.h < 170` 같은 px 고정
임계값 때문에 손글씨로 분류되고, 위쪽에 그린 교환 화살표도 손글씨가 된다. 당시 AI는 구분선을 `5 3 8 1`로,
화살표를 `3`으로 읽었고 피드백 "5와 3이라고"로 이어졌다. 보정용에서는 길쭉한 `8`이 상자로(015855),
