# 인식 구조 개선 실행 계획

설계: [recognition-redesign.md](recognition-redesign.md)

상태: 설계만 작성. 아래 항목은 아직 구현하지 않았다.

## 1. 기준선과 작업 범위

이 브랜치는 `411fd5d`의 독립 워크트리다.
원래 작업 폴더의 미커밋 실행 검증·로그 개선은 진단에 참고했지만 이 브랜치에 복사하지 않았다.
구현을 시작할 때는 그 변경의 소유자와 통합 기준을 확인하고, 확정된 기준에서 새 구현 브랜치를 만든다.
여기서의 설계 작성 때문에 원래 작업 폴더의 코드·로그·설정 파일을 바꾸지 않는다.

유지할 기존 계약:

- `InkBus`와 페이지 좌표, 원본 stroke ID, `Pipeline.say()`.
- `Op`, `Engine`, `Player`, `AnimationOverlay`, `hideStrokes`의 렌더링 흐름.
- 완성된 단계 검증, 확정 발화 단위 실행 ID, 중복 실행 방지, 페이지 epoch 무효화.
- request 생명주기 기록과 로그 저장 ACK/재전송 중복 제거.
- 기존 라벨 주입 평가와 회귀 테스트.

추가 책임은 기존 파일에서 역할을 분리해 배치한다.
아래 파일명은 제안이며 공유 계약을 먼저 고정한다.

| 위치 | 책임 |
| --- | --- |
| `src/animation/scene/types.ts` | 객체·관계·패치·버전 참조 계약과 런타임 검증 |
| `src/animation/scene/store.ts` | 원본 인덱스, 해석 revision, 획 소유권, 원자적 패치 |
| `src/animation/scene/renderBoard.ts` | 실행 가능한 entity를 Engine 조회 형태로 투영 |
| `src/animation/perception/snapshot.ts` | 효과 없는 원본 crop, 문맥 이미지, 좌표 대응 |
| `src/animation/perception/scheduler.ts` | 영역 병합, 요청 예산, 관련 버전 검사 |
| `src/animation/perception/client.ts` | 시각 관측 요청과 완성 응답 파싱 |
| `src/animation/intent.ts` | 발화 원문/후보, 지시 대상 문맥, 의미 결정 |
| `src/animation/planner.ts` | 의미 동작을 검증 가능한 Op 단계로 변환 |
| `src/animation/pipeline.ts` | 입력·인식·의도·실행 조정 |
| `src/evals/` | 정답 주입 없는 인식 및 전체 시간 재현 평가 |

## 2. 단계 0 — 비교 기준과 호출 상태 확보

작업:

- 통합 기준 커밋과 실행 가능한 기존 테스트 결과를 기록한다.
- 원본 획/이미지, 사람이 확인한 장면, 기대 동작을 연결하는 평가 manifest를 정의한다.
- 기존 정렬·도형·경로 사례를 분리해 보정용과 검증용 데이터의 경계를 고정한다.
- aiStatus 전이와 received/호출 제외 사유를 기록하고 제한된 재연결을 넣는다.
- 키 존재, 프록시 접근, 실제 모델 호출 성공을 패널에서 구분한다.

완료 조건:

- AI 호출이 없는 입력도 이유를 찾을 수 있다.
- 연결 실패/복구 테스트에서 만료 발화가 실행되지 않는다.
- 기존 라벨 주입 평가와 새 인식 평가의 이름·분모가 구분된다.

검증: 연결 실패·403·키 없음·복구의 모의 테스트, 기존 단위 테스트.
이 단계에서 실제 API가 필요한 기준 측정은 실행 전 사용량을 추정해 제한된 사례부터 시작한다.

## 3. 단계 1 — SceneStore를 기존 경로 옆에 도입

작업:

- 기존 획 이벤트를 불변 원본 저장소와 SceneStore에 투영한다.
- 기하 분류를 후보로 만들고 number/text/shape/connector/annotation을 재분류할 수 있게 한다.
- revision, merge/split, 획 소유권, 관계 무효화와 typed/correction 우선순위를 구현한다.
- 개발 패널의 객체 선택·종류/값 정정 동선을 같은 패치 경로에 연결한다.
- 장면 상태는 로그에 남기되 화면 실행은 기존 경로만 담당한다.

완료 조건:

- box 후보를 number로 바꾸고, 여러 획을 도형 하나로 묶을 수 있다.
- merge/split 뒤 이전 EntityRef를 재사용할 수 없다.
- 부모 개념과 자식 실행 객체가 획을 이중 소유하지 않는다.
- 원본 좌표와 애니메이션 transform이 서로 덮어쓰지 않는다.

검증: 상태 불변식과 버전 경합 테스트.
아직 LLM이 없어도 수동 패치로 데이터 계약을 검증할 수 있어야 한다.

## 4. 단계 2 — 수정 가능한 시각 인식

작업:

- 기하 분류에 관계없이 관련 원본 stroke 전체를 관측한다.
- 원본 crop과 ID 대응, 페이지 개요를 생성하고 실행 효과를 제외한다.
- 영역 debounce/최대 대기/단일 진행/후속 한 묶음을 구현한다.
- 이미지 요청의 region/source revision을 검사하고 정정 가능한 패치를 반영한다.
- 숫자 8, X 도형, 밑줄, 화살표 머리, 여러 획 글자를 평가한다.

완료 조건:

- 8이 초기 box 분류 때문에 값 목록에서 영구 제외되지 않는다.
- 도형에 역할을 붙일 수 있으며 OCR 글자 판독으로 강제하지 않는다.
- 연속 입력이 매번 요청을 중단하지 않고 안정된 영역은 결과가 적용된다.
- 관련 새 획은 오래된 결과를 막고 무관한 획은 유효한 판독을 막지 않는다.
- 같은 불확실한 관측의 자동 재시도가 한 번을 넘지 않는다.

검증: 원본 이미지 생성 경로를 사용하는 브라우저 인식 평가.
사람의 정답 라벨은 채점에만 사용하고 시스템 입력에 주입하지 않는다.

## 5. 단계 3 — 의미 결정과 로컬 계획 분리

작업:

- final 원문과 전사 후보, 지시 대상의 근거와 revision을 저장한다.
- comparison/state-change/correction/irrelevant/ambiguous와 의미 동작 계약을 구현한다.
- 인식이 늦으면 awaiting-scene에서 기다리고 같은 발화를 다시 대상 해석한다.
- 정규식 최종 허용 게이트를 의미 결정 + 구조 검증으로 교체한다.
- 비교, 교환, 이동, 흐름, 정지, 스타일, 생성, 정렬을 기존 Op로 컴파일한다.
- interim 모델 호출은 초기 기본값에서 끄고 일시 강조만 허용한다.

완료 조건:

- 인식 완료 전 들어온 명시적 교환 발화가 인식 후 올바른 대상에 적용된다.
- 새 비교가 모호하면 이전 비교 쌍을 잘못 가져오지 않는다.
- 부정·가정·질문·잡담은 해당 의미에 맞게 처리된다.
- 단어 목록에 없는 설명도 지원하는 의미 동작으로 변환할 수 있다.
- 같은 utterance 재처리는 중복 커밋하지 않고 새 utterance의 재교환은 허용한다.

검증: 고정 장면에서 의미 결정 평가와 로컬 계획 테스트.
이 단계까지는 새 계획을 실행하지 않고 기존 출력과 나란히 기록해 차이를 검토한다.

## 6. 단계 4 — 엔진과 편집기 연결

작업:

- Engine의 Board 의존을 최소 조회 인터페이스로 분리한다.
- RenderBoard를 통해 semantic leaf entity를 그리되 원본 stroke ID를 보존한다.
- 관계·공간 점유·관련 배치 revision을 실행 read set으로 검사한다.
- 이동한 객체의 가리키기/지우기/덧필기 hit-test를 원본 ID로 역매핑한다.
- 덧필기 입력의 원본 좌표는 보존하고 기준 좌표로의 stroke binding과 revision을 기록한다.
- 수정·삭제·페이지 전환·진행 중 정정의 취소 규칙을 구현한다.
- 컨테이너 포함과 숫자 슬롯 충돌을 구분한다.

완료 조건:

- 교환은 한 단계 전체가 커밋되고 반쪽 이동이 없다.
- 다중 획 도형이 하나로 움직이며 이중 그리기/이중 숨김이 없다.
- 움직인 객체를 현재 보이는 위치에서 가리키고 수정할 수 있다.
- 도형의 정상 겹침은 허용하고, 배열 원소의 잘못된 겹침은 거부한다.
- 각 입력에 대해 기존 경로와 새 경로 중 하나만 화면을 구동한다.

검증: 기존 Engine/Player 회귀, 브라우저 데스크톱·태블릿 크기 화면,
실제 획·interim·final을 겹쳐 재생하는 전체 경로 평가.

## 7. 단계 5 — 전체 평가와 승격

작업:

- 정답 주입 없는 동일 입력을 기존/새 경로에 재생한다.
- 인식, 대상 해석, 오작동, 누락, 보류, 지연, 요청 수/사용량을 각각 비교한다.
- 보정에 쓰지 않은 세션에서 설계 문서의 수용 기준을 평가한다.
- 새 경로를 기본으로 바꿀 조건과 기존 경로로 돌아갈 설정을 문서화한다.

완료 조건:

- 결정적 회귀 시나리오가 모두 통과한다.
- 오작동을 줄이면서 필요한 실행 완료율도 유지하거나 개선한다.
- OCR 제외 순차 평가만으로 전체 품질이 개선됐다고 결론 내리지 않는다.
- 지연 목표를 초과한 부분은 인식 대기/의미 해석/재생 중 어느 단계인지 설명할 수 있다.
- 검증에 사용한 표본 수, 반복 횟수, 모델 설정과 토큰/비용이 보고서에 남는다.

## 8. 구현 중 중단·재설계 조건

- 그룹 변경 때문에 획 소유권이나 현재 위치를 일관되게 복원할 수 없으면 엔진 승격을 멈춘다.
- 잘못된 실행은 줄었지만 필요한 동작도 대부분 보류하면 대상 해석과 인식 수용 기준을 재검토한다.
- 요청을 분리한 뒤 지연/비용이 늘면 호출 빈도와 crop/문맥 예산부터 조정한다.
- 전사 오류가 주된 실패 요인으로 남으면 사람이 확인한 평가 음성으로 음성 엔진 실험을 분리한다.
- 다른 모델을 시험할 때에도 데이터·프롬프트 역할·설정·채점 기준을 고정해 구조 변경 효과와 구분한다.

설계 단계에서는 새 의존성 설치, API 평가 실행, 애플리케이션 코드 변경, 커밋/푸시를 수행하지 않는다.
